# Вход через Microsoft Entra ID (Azure AD)

Umbrella принимает пользователей облачного каталога Microsoft Entra ID по OpenID Connect: поток authorization code с PKCE, конфиденциальный клиент с секретом. Настройка находится на странице **Настройки → LDAP / AD / Entra ID**, под параметрами LDAP. Вход через LDAP / AD и через Entra ID можно включать независимо.

## Регистрация приложения в Entra ID

1. Портал Entra → **App registrations → New registration**. Supported account types: **Accounts in this organizational directory only** (один клиент).
2. **Redirect URI**: платформа **Web**, адрес из поля «URI перенаправления» на странице настроек, например `https://umbrella.example.com/api/auth/entra/callback`. Адрес должен совпадать с тем, по которому пользователи открывают Umbrella.
3. **Certificates & secrets → New client secret**. В Umbrella вводится значение секрета (Value), не его ID. Секрет сохраняется в OpenBao (путь `entra`, ключ `client_secret` в mount Umbrella), в состоянии Umbrella остаётся только ссылка.
4. **API permissions**: делегированное разрешение Microsoft Graph `User.Read` (есть по умолчанию). Через него Umbrella читает профиль (должность, отдел, руководитель, фото) и членство в группах, включая вложенные.
5. Скопируйте **Directory (tenant) ID** и **Application (client) ID** со страницы Overview.

## Настройки в Umbrella

| Поле | Что указать |
| --- | --- |
| Облако Microsoft | глобальное, US Government или Китай (21Vianet) |
| ID каталога (клиента) | GUID клиента или его домен (`contoso.onmicrosoft.com`); `common` и `organizations` не принимаются |
| ID приложения (клиента) | Application (client) ID |
| Секрет клиента | значение секрета; при повторном сохранении можно оставить пустым |
| Группа администраторов | Object ID группы; её участники (в том числе через вложенные группы) получают роль администратора при каждом входе |
| Группа допущенных пользователей | Object ID группы; если задана, войти могут только её участники и администраторы |

«Проверить подключение» находит клиента по OpenID-конфигурации и проверяет ID приложения и секрет (запрос токена client credentials). Перед сохранением выполняется та же проверка.

## Как устроен вход

- На странице входа появляется кнопка «Войти через Microsoft». Пользователь уходит на страницу входа Microsoft и возвращается на `/api/auth/entra/callback`.
- Umbrella проверяет `state` (и cookie браузера, начавшего вход), обменивает код на токены с `code_verifier`, проверяет подпись ID-токена по ключам клиента, издателя, аудиторию, срок, `nonce` и `tid`.
- Учётная запись создаётся с источником «Entra ID», логин — `preferred_username` (UPN) в нижнем регистре. Запись привязывается к неизменяемому `oid`: если UPN позже займёт другой человек, войти в чужую запись он не сможет.
- Профиль и роль администратора обновляются при каждом входе. Пароль у таких записей нет, вход по паролю для них отклоняется.
- Выключение входа через Entra ID завершает сессии пользователей Entra ID. Выключить его нельзя, если нет активного локального администратора.
