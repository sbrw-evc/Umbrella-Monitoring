# Umbrella MVP: приложение

Реализация MVP по архитектуре из [`mvp/docs`](../mvp/docs). Backend на Go, веб-интерфейс на React и TypeScript, секреты в OpenBao.

Коннекторы, приём вебхуков и визуальный конструктор по плану из [`n8n.md`](../n8n.md): [docs/connectors.md](docs/connectors.md).

Обработка в backend:

- **Секреты.** Единственное хранилище — OpenBao (KV v2). Всё, что вводится в интерфейсе или API (пароли и токены систем, ключи PagerDuty, адреса вебхуков, секреты блоков), сразу пишется в `umbrella/<объект>/<id>`, в приложении остаётся ссылка `openbao://umbrella/…#ключ`. Значения читаются при использовании и кешируются на 30 с, поэтому ротация в OpenBao не требует изменений в Umbrella. Вход по AppRole (role_id и secret_id из файлов) или токеном, продление токена, повторный вход при отказе. Переменные окружения с секретами задаются ссылками `openbao://…`. При удалении интеграции или канала их секреты удаляются из OpenBao.
- **Хранение состояния.** Всё состояние (КЕ, связи, инциденты, события, коннекторы, интеграции, правила, команды, пользователи, роли, токены, каналы, настройки) сохраняется каждые 2 секунды и при остановке: в файл `UMBRELLA_DATA_DIR/umbrella.gob` (предыдущая версия — `.bak`) или в PostgreSQL (таблица `umbrella_state`, текущая и предыдущая версии, запись в одной транзакции). Хранилище выбирается мастером или в «Настройках» и переключается на ходу с переносом данных; подключение к БД запоминается в `UMBRELLA_DATA_DIR/storage.json`, пароль — только ссылкой на OpenBao. При старте Umbrella ждёт базу до 2 минут. Сессии тоже сохраняются, поэтому после обновления пользователи остаются в системе. Повреждённый снимок не перезаписывается: запуск останавливается с ошибкой.
- **Приём.** `POST /api/ingest/{slug}` выполняет опубликованную версию коннектора и отвечает 202 только после записи событий. Токен приёма проверяется по OpenBao (`X-Umbrella-Token` или `Authorization: Bearer`). Pull-коннекторы опрашивают источник с авторизацией Basic, Bearer, ApiKey или своим заголовком.
- **Блоки.** Входящий webhook, расписание, HTTP-запрос, парсинг JSON, key=value, regex, CSV, фильтр, справочник severity, метки, шаблон источника с подстановками `${путь}`, `${поле|значение}`, `${поле|$другое|$третье}`, подтверждение, событие.
- **CMDB Discovery.** Zabbix (узлы), Prometheus (цели) и NetBox (устройства и ВМ) загружаются как КЕ по расписанию и по кнопке. Один хост из разных систем — одна КЕ: сопоставление по ID в источнике, имени и DNS, IP. NetBox задаёт название, тип, команду и ответственных (контакты объекта, площадки или арендатора). Пропавшие из источника объекты получают метку или удаляются.
- **Схлопывание и жизненный цикл.** Ключ = КЕ + сигнал; severity = максимум по источникам; resolve, когда в норму вернулись все источники; повторное открытие в окне 10 минут; RED и USE одной услуги связываются как «вероятная причина».
- **Rule Engine.** Правила RED и USE вычисляют PromQL по источнику метрик с интервалом правила. Серия выше порога дольше `for` даёт событие firing на КЕ из метки, возврат в норму или пропажа серии — resolved. Состояние серий сохраняется, поэтому перезапуск не теряет и не дублирует срабатывания.
- **PagerDuty Gateway.** Events API v2 (US или EU), `dedup_key = umb-<id>`, маршрут по команде и ИТ-сервису, ответственные КЕ в `custom_details`, порог важности. Ошибки 429 и 5xx повторяются с backoff, 400 не повторяется; circuit breaker после 5 ошибок подряд. Недоставленные trigger, acknowledge и resolve повторяются раз в минуту и после перезапуска; после восстановления PagerDuty досылается acknowledge или resolve. Webhooks v3 проверяются по подписи (без секрета вебхук отклоняется), тревога находится по `incident_key`, ID инцидента или алертам инцидента через REST API; события triggered, acknowledged, resolved, reassigned, escalated, annotated, priority_updated попадают в хронологию. Дежурные синхронизируются раз в 5 минут.
- **Резервное оповещение.** Тревога error или critical, не принятая PagerDuty за 2 минуты (в том числе когда PagerDuty не подключён), получает отметку «Резерв»; каналы в режиме «при отказе PagerDuty» получают её с дежурными из PagerDuty и ответственными КЕ.
- **Аутентификация и авторизация.** Без изменений: сессии в HttpOnly-cookie с CSRF, API-токены, PBKDF2, блокировки, разрешения на каждый маршрут, области по бизнес-услугам. Новые разрешения: `rules.edit`, `integrations.edit`.
- **Очистка.** `DELETE /api/incidents/{id}` (администратор) удаляет инцидент с событиями, `DELETE /api/parse-errors?connector=` — ошибки разбора коннектора; так smoke-test стенда убирает за собой. Журнал аудита не очищается.
- **Метрики.** `GET /metrics`: инциденты, события, ошибки разбора, доставки, КЕ, пользователи, срабатывания и ошибки правил, состояние интеграций, PagerDuty (включён, circuit breaker, очередь, доставки).
- **Grafana.** `/go/incidents/{id}/grafana` открывает дашборд из настроек с окном ±10 минут и переменными `var-ci`, `var-service`, `var-incident`; без настройки ссылка в интерфейсе не показывается.

## Чего пока нет

- Реляционная схема PostgreSQL (сейчас состояние хранится снимком в одной таблице) и NATS JetStream вместо внутренних вызовов.
- Вход через OIDC и синхронизация групп каталога.
- Резервное оповещение по почте и одноразовые ссылки подтверждения, Context Builder (генерация дашборда Grafana под инцидент).

Этих функций нет и в интерфейсе.

## Запуск

Нужны Go 1.24+, Node.js 20+, OpenBao и (по желанию) PostgreSQL 13+ для хранения состояния. Для разработки OpenBao поднимается в dev-режиме:

```bash
cd app
make openbao-dev                 # контейнер OpenBao, KV v2 umbrella/
export UMBRELLA_OPENBAO_ADDR=http://127.0.0.1:8200 UMBRELLA_OPENBAO_TOKEN=dev-root
make build
make run                         # http://localhost:8080, состояние в backend/data
```

Без OpenBao приложение запускается, но секреты сохранить нельзя: интеграции, PagerDuty и каналы недоступны, на странице «Интеграции» показывается предупреждение.

Режим разработки с горячей перезагрузкой: `make dev-api` и `make dev-web` (интерфейс на :5173). Образ: `make image` (версия из `git describe` попадает в `X-Umbrella-Version`). Полный стенд с OpenBao, Zabbix, Prometheus, логами через Kafka, NetBox и Grafana и скрипт обновления без потери данных: [deploy/lab](../deploy/lab/README.md).

При первом запуске открывается мастер настройки. Если задан `UMBRELLA_ADMIN_PASSWORD` (значение или ссылка `openbao://…`), администратор `UMBRELLA_ADMIN_USER` создаётся сразу и проходит мастер после входа; иначе администратора создаёт мастер, а сервер пишет в журнал код установки (`setup_code`) и кладёт его в `UMBRELLA_DATA_DIR/setup-token`. Повторно мастер не запускается.


## Интерфейс

Компоновка рассчитана на инженеров мониторинга и дежурных:
- узкая светлая панель навигации слева (иконки с подсказками, раскрывается до подписей) с группами Обзор, Сбор данных, Обработка, Администрирование и пунктом Настройки внизу;
- верхняя строка: поиск инцидентов, область видимости (команды), язык, быстрый переключатель светлой и тёмной темы, состояние связи, пользователь;
- слева от рабочей области — вторичная панель со списками и сохранёнными фильтрами;
- над таблицей — плитки-счётчики; метки важности и статусов мягкие, с цветной точкой;
- карточки объектов открываются боковой панелью с вкладками; конструктор устроен как палитра блоков, холст и инспектор.

### Темы

Встроены светлая (по умолчанию) и тёмная. Все цвета интерфейса — CSS-переменные `--<элемент>-<цвет>`, в `styles.css` нет цветовых литералов. В «Настройки → Темы» можно скачать шаблон JSON (на основе светлой или тёмной), в котором цвета сгруппированы по элементам: `app`, `accent`, `rail`, `topbar`, `sideList`, `button`, `input`, `table`, `severity`, `status`, `pagerduty`, `tag`, `graph`, `blocks`, `chart`, `overlay`, `toast`, `code`. Заполненный файл загружается там же, тема появляется в списке и применяется. Незаполненные цвета берутся из основы (`base`). Неизвестные элементы и неверные цвета отклоняются с понятной ошибкой.

### Языки

Встроены русский (по умолчанию) и английский. В «Настройки → Языки» можно скачать шаблон JSON со всеми строками, сгруппированными по страницам и элементам (`common`, `menu`, `incidents`, `ops`, `cmdb`, `cis`, `integrations`, `connectors`, `editor`, `blocks`, `events`, `parseErrors`, `rules`, `maintenance`, `selfcheck`, `audit`, `auth`, `account`, `users`, `roles`, `notifications`, `settings`). Подстановки `{n}` сохраняются, формы множественного числа задаются категориями `one`, `few`, `many`, `other`. Загруженный язык появляется в переключателе, показывает процент перевода, непереведённые строки берутся из английского. Файл с кодом `ru` или `en` заменяет встроенный перевод. Даты и время форматируются по `dateLocale`.

### Анимация

Смена темы раскрывается кругом от точки щелчка, смена языка — плавной сменой страницы (View Transitions API; в браузерах без него цвета темы меняются плавным переходом). Анимированы появление страниц, карточек, плиток и строк таблиц (по очереди), блоков и связей в конструкторе и графе, боковых панелей, окон, меню и уведомлений, ячеек тепловой карты и столбиков графиков, ошибки форм. В «Настройки» выбирается режим анимации: как в системе (учитывает «уменьшение движения» ОС), всегда или выключена.

Загруженные темы и языки хранятся в браузере (localStorage). Данные с сервера (названия КЕ, тревог, правил, записи хронологии) показываются как есть.
