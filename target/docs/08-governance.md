# Umbrella · целевая архитектура · 8. Управление архитектурой

Разработка целевой архитектуры стоит 40–45 человеко-месяцев за 8 месяцев (месяцы 7–14) командой 5,5 человека и 2 штатные единицы на поддержку; лицензий нет, платные только PagerDuty и тарифы SMS- и голосового шлюза. Ниже стоимость и эффекты, требования с трассировкой, журнал решений, ответственность, проверки, риски и ограничения.

## Журнал архитектурных решений

«Принято» означает решение заказчика с датой; «Предложено» означает рекомендацию архитектуры, которую нужно утвердить; «Заменено» означает, что решение действовало на предыдущем этапе и заменено указанным.

| № | Решение | Альтернативы | Обоснование | Статус |
| --- | --- | --- | --- | --- |
| ADR-01 | Своя разработка вместо готовой event-management платформы | коммерческие платформы, open source аналоги | нужен конструктор с ack в источник, устойчивые КЕ для облака, РСМ и резервное оповещение без лицензий | Предложено |
| ADR-02 | PagerDuty — основной канал оповещения, резервные каналы в Umbrella | только PagerDuty; своя полная доставка | готовые расписания и эскалации PagerDuty, но нельзя остаться без оповещения при его недоступности | Принято 30.09.2026 |
| ADR-03 | Go на бэкенде | Java, Python | производительность, один бинарник, SDK облаков | Принято 30.09.2026 |
| ADR-04 | NATS JetStream как шина | Kafka, RabbitMQ | хватает с запасом для 330 событий в секунду, request/reply и зеркалирование на вторую площадку, проще в эксплуатации | Предложено |
| ADR-05 | PostgreSQL; transactional outbox: изменение тревоги и запись outbox в одной транзакции | MongoDB, состояние в шине | реляционная карта CMDB, транзакции, нет потерь между базой и шиной | Предложено |
| ADR-06 | Конструктор коннекторов на своём движке в Go | Node-RED, Apache NiFi | ack после записи и inbox, один рантайм | Предложено |
| ADR-07 | Ack источнику только после записи в шину | ack сразу | нет потерь и дублей | Принято 30.09.2026 |
| ADR-08 | Устойчивая КЕ в облаке = логическая группа или тег | КЕ на каждый инстанс | ID меняется после перезагрузки | Предложено |
| ADR-09 | Без платных российских продуктов, open source допустим | — | требование заказчика | Принято 30.09.2026 |
| ADR-10 | Ключ дедупликации = КЕ + сигнал (+ метки) | хеш текста | работает между источниками | Предложено |
| ADR-11 | История событий в ClickHouse, 13 месяцев, агрегаты 3 года | хранить в PostgreSQL; полнотекстовые поисковые движки | сжатие и быстрые агрегаты; open source, соответствует ADR-09 | Предложено |
| ADR-12 | Все секреты только в OpenBao | зашифрованные поля в БД; Kubernetes Secrets | требование заказчика; единое место, аудит, ротация | Принято 30.09.2026 |
| ADR-13 | Fallback Notifier отдельным контейнером | внутри PagerDuty Gateway | отказ или ошибка в одном не выключает другой, отдельное масштабирование и права | Предложено |
| ADR-14 | Кеш дежурств из PagerDuty REST API каждые 5 мин | ручной список дежурных; запрос в момент аварии | в момент недоступности PagerDuty его API тоже может не отвечать | Предложено |
| ADR-15 | Резервные каналы только почта и webhook, подтверждение по одноразовой ссылке в Core API | сразу SMS и звонки | без новых подрядчиков на первом этапе | Заменено ADR-19 |
| ADR-16 | Вторая площадка в тёплом резерве | холодный резерв; активный-активный | RTO 15 мин без сложности активного-активного режима | Предложено |
| ADR-17 | Correlation Engine отдельным контейнером, детерминированная корреляция по графу КЕ | корреляция в Alert Engine; ML-платформа | отдельное масштабирование, объяснимость | Предложено |
| ADR-18 | ITSM Sync: корпоративная CMDB — мастер бизнес-услуг, Umbrella — мастер технических КЕ | Umbrella мастер всего; только ручной ввод | нет двух мастеров для одних данных | Предложено |
| ADR-19 | Полный набор резервных каналов с подтверждением из сообщения и эскалацией по уровням escalation policy | только почта и webhook (ADR-15) | почта ночью не будит; нужны звонок и SMS независимо от PagerDuty | Предложено |
| ADR-20 | Дашборд инцидентов в собственном веб-интерфейсе, а не дашборд Grafana | дашборд инцидентов в Grafana; только PagerDuty | нужны RBAC с областями, действия (ack, silence), поиск по событиям и истории, состояние резервного оповещения | Принято 01.10.2026 |
| ADR-21 | Контекст инцидента в Grafana: дашборд генерируется по HTTP API из low-code «Связей контекста» | свои графики в Umbrella; один шаблонный дашборд с переменными в URL | Umbrella не хранит телеметрию; учитываются связи КЕ по карте и тип КЕ | Принято 01.10.2026 |
| ADR-22 | Ролевая модель: каталог — источник истины, группы → роли + области + предустановки; LDAPS или SCIM | локальные пользователи и роли в Umbrella | один источник истины, автоматический отзыв доступа, те же группы для Grafana, аудит | Принято 01.10.2026 |
| ADR-23 | Секреты только в OpenBao; начальные секреты: auto-unseal (transit второго экземпляра или KMS) либо Шамир 3 из 5 у хранителей | ключи распечатывания у одного администратора; Kubernetes Secrets | нет единой точки компрометации и потери; root token отозван; способ распечатывания выбирает ИБ | Предложено |
| ADR-24 | Один алерт PagerDuty на инцидент: dedup_key umb-inc-‹id инцидента›; каждая тревога сразу входит в инцидент из одной или нескольких тревог | алерт на каждую тревогу; ожидание окна корреляции перед отправкой | меньше шума у дежурных без задержки оповещения | Предложено |

## Ответственность и проверка

Матрица RACI: R делает, A отвечает, C консультирует, I информируется.

| Активность | Владелец архитектуры | Инженеры мониторинга | Команда разработки | ИБ | Эксплуатация | Администратор ролей |
| --- | --- | --- | --- | --- | --- | --- |
| Архитектура и ADR | A, R | C | C | C | C | I |
| Коннекторы, шаблоны, правила корреляции | A | R | C | I | I | — |
| Правила подавления и маршрутизация | A | R | I | C | I | — |
| Резервные каналы и контакты | A | R | C | C | R | — |
| «Связи контекста» и дашборды Grafana | A | R | C | C | C | — |
| Роли, привязки групп, предустановки дашборда | A | C | I | C | I | R |
| Интеграция с ITSM | A | C | R | C | C | — |
| Разработка и тесты | A | C | R | C | C | — |
| Модель угроз и пентест | A | I | C | R | C | I |
| Эксплуатация, DR-учения, бэкапы, хранение ключей распечатывания | A | I | C | C | R | — |

| Проверка | Критерий приёмки | Когда |
| --- | --- | --- |
| Нагрузочный тест | 40 000 событий в минуту, p95 от события до PagerDuty не больше 30 с | этап 10 и каждый релиз |
| Тест подтверждения | останов Connector Runtime между записью и ack: 0 потерь, 0 дублей | каждый релиз |
| Тест облачных ID | пересоздание инстанса не меняет КЕ | каждый релиз |
| Тест резервных каналов | блокировка PagerDuty: SMS и звонок за 3 мин, ack из сообщения, эскалация по таймауту уровня, возврат без дублей | этап 7 и каждый релиз; каналы ежедневно |
| Хаос-тест | потеря узла NATS, PostgreSQL, ClickHouse или app-узла без потери алертов | до эксплуатации, раз в квартал |
| Watchdog | сквозная проба до PagerDuty Gateway раз в минуту, heartbeat, проверка каналов раз в сутки | постоянно |
| DR-учения | переключение на резервную площадку за 15 мин, потери не больше 1 мин, восстановление OpenBao из снапшота | раз в полгода |
| Тест корреляции | набор исторических аварий: верная причина в 60%, один алерт PagerDuty на инцидент | этап 8 и раз в квартал |
| Проверка контекста Grafana | эталонные инциденты: дашборд открывается за 2 с, панели и окно соответствуют правилам, причина выделена | каждый релиз |
| Тест синхронизации ролей | исключение из группы каталога: доступ, сессии и команда Grafana отозваны не позже 15 мин; самоназначение прав невозможно | каждый релиз |
| Сверка с ITSM | расхождения КЕ и бизнес-услуг меньше 1% | ежедневно |
| Пентест и ревью модели угроз | нет открытых уязвимостей высокого уровня | до эксплуатации, далее раз в полгода |

## Риски и ограничения

| Риск | Вероятность | Влияние | Мера |
| --- | --- | --- | --- |
| Umbrella становится единой точкой отказа оповещения | средняя | высокое | реплики без SPOF, вторая площадка, внешний heartbeat, резервные каналы, план возврата к прямым интеграциям |
| SMS- и голосовой шлюз недоступен одновременно с PagerDuty | низкая | высокое | второй поставщик по резервному маршруту, запасная платформа как следующий канал, внутренний мессенджер |
| Ложная корреляция скрывает отдельную проблему | средняя | высокое | объяснимые правила, ручное разделение инцидента, отчёт точности |
| Потеря ключей распечатывания OpenBao | низкая | высокое | auto-unseal или Шамир 3 из 5 у разных хранителей, регламент хранения, проверка на DR-учениях |
| Кеш дежурств устарел | низкая | среднее | обновление каждые 5 мин, расписания на 7 дней вперёд, резервные контакты при кеше старше 24 ч |
| Источники и облака без устойчивых тегов дают много событий «без КЕ» | высокая | среднее | политика тегов, очередь «без КЕ», сервис PagerDuty по умолчанию |
| Grafana недоступна | средняя | низкое | дашборд инцидентов и боковая панель работают, ссылка показывает ошибку; оповещение не затронуто |
| Каталог недоступен | низкая | среднее | группы последней синхронизации, вход по OIDC, break-glass |
| Конфликты данных с корпоративной CMDB | высокая | среднее | чёткое разделение мастеров, ревью конфликтов |
| Рост объёма истории сверх оценки | средняя | среднее | TTL и агрегаты, мониторинг дисков ClickHouse, расширение при 70% |
| Резервная площадка устаревает и не поднимается | средняя | высокое | GitOps для обеих площадок, Watchdog следит за отставанием, учения раз в полгода |
| Конструктор и редактор «Связей контекста» слишком сложны для инженеров | средняя | высокое | библиотека шаблонов и правил, dry-run, юзабилити-тесты |
| Стоимость SMS и звонков при шторме | низкая | среднее | только error и critical, сводки, лимиты и бюджет на канал |

Ограничения:

- Метрики, логи и трейсы не хранятся; графики строит Grafana по данным существующих хранилищ.
- ML не принимает решений, только предлагает правила корреляции.
- Активного-активного режима нет: резервная площадка в тёплом резерве.
- Права выдаются только через группы каталога, кроме аварийного администратора.
- Платные российские продукты не используются; все секреты только в OpenBao.
