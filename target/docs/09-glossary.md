# Umbrella · целевая архитектура · 9. Глоссарий

Термины, которые используются в документах набора целевой архитектуры; сначала латиница, затем кириллица, по алфавиту.

## Термины

| Термин | Значение |
| --- | --- |
| ack (подтверждение) | 1) ответ источнику, что событие получено и записано в шину; 2) подтверждение инцидента дежурным в PagerDuty, на дашборде инцидентов или по резервному каналу |
| AD (Active Directory) | пример корпоративного каталога, который служит источником истины для пользователей и групп |
| ADR | запись в журнале архитектурных решений: решение, альтернативы, обоснование, статус |
| AIOps | применение статистики и машинного обучения к событиям эксплуатации; в Umbrella ML только предлагает правила корреляции |
| backoff | увеличение паузы между повторными попытками после ошибки |
| BPMN | нотация описания бизнес-процессов с дорожками участников, задачами и шлюзами |
| break-glass | локальная учётная запись аварийного администратора на случай недоступности IdP или каталога; учётные данные в OpenBao, MFA, аудит каждого использования |
| C4 | нотация описания архитектуры по уровням: контекст, контейнеры, компоненты, развёртывание |
| CEL | язык выражений для условий и маппинга, безопасно исполняется на сервере |
| circuit breaker | автомат, который после 5 ошибок подряд или 60 с без ответа считает канал PagerDuty деградировавшим и прекращает попытки отправки |
| ClickHouse | колоночная СУБД open source для истории событий, тревог и инцидентов и отчётов |
| CMDB, карта CMDB | база КЕ и связей; в Umbrella строится из данных мониторинга и обменивается данными с корпоративной CMDB |
| Context Builder | контейнер, который генерирует дашборд Grafana для инцидента по «Связям контекста» |
| Correlation Engine | контейнер топологической корреляции тревог в инциденты с вероятной причиной |
| dedup_key | ключ алерта в PagerDuty; у Umbrella формат umb-inc-‹id инцидента› |
| DLQ | очередь неразобранных сообщений; в Umbrella поток events.dlq с исходным телом события |
| DMZ | сетевая зона между интернетом и внутренними зонами; в ней reverse proxy с WAF и egress-прокси |
| dry-run | прогон настройки на реальных данных без публикации |
| egress-прокси | единственная точка выхода Umbrella во внешние сети, пропускает только адреса из списка |
| escalation policy | правила PagerDuty: кого и через какое время оповещать по уровням; Umbrella копирует их в кеш дежурств |
| external_id | идентификатор события в источнике; вместе с источником даёт ключ inbox |
| Fallback Notifier | контейнер резервного оповещения |
| GitOps | управление развёртыванием через описание в Git, которое автоматически применяется к кластерам |
| Grafana | система визуализации; в Umbrella показывает метрики, логи и трейсы инцидента на сгенерированном дашборде |
| Grok | шаблоны разбора текстовых строк на поля на основе регулярных выражений |
| heartbeat | регулярный сигнал «жив» во внешний сервис; если он пропал, внешний сервис сам поднимает тревогу |
| History Service | контейнер истории событий, тревог и инцидентов и отчётов |
| HMAC | подпись сообщения общим секретом; проверяет подлинность webhooks и ссылок подтверждения |
| HPA | автоматическое масштабирование числа подов Kubernetes по нагрузке |
| IdP | корпоративный поставщик учётных записей и входа |
| Inventory DB | приложение учёта инвентаря ЦОД в духе NetBox (площадки, стойки, устройства, IP, кабели); источник физических КЕ для карты CMDB и получатель статусов тревог |
| inbox | таблица полученных событий для отбрасывания повторов по ключу источник + external_id |
| ITSM, ITSM Sync | система управления ИТ-услугами; контейнер обмена с корпоративной CMDB и ITSM |
| JSONata | язык запросов и преобразования JSON для маппинга полей |
| Keeper (ClickHouse Keeper) | служба координации кластера ClickHouse, хранит состояние репликации |
| LDAP, LDAPS | протокол доступа к каталогу; LDAPS — LDAP поверх TLS, порт 636 |
| low-code | настройка в визуальном редакторе из блоков без программирования |
| mTLS | TLS с взаимной проверкой сертификатов клиента и сервера |
| MTTA, MTTR | среднее время до подтверждения и до устранения |
| OIDC | протокол входа через IdP поверх OAuth 2.0 |
| OpenBao | хранилище секретов open source; в Umbrella единственное место для всех секретов |
| OpenTelemetry | открытый стандарт сбора трассировок и метрик приложений |
| outbox, transactional outbox | таблица исходящих сообщений, запись в которую делается в одной транзакции с изменением данных; отдельный компонент публикует её в шину или внешнюю систему с повторами |
| p95 | 95-й процентиль: 95% измерений не больше этого значения |
| PDB | PodDisruptionBudget: ограничение Kubernetes на число одновременно остановленных подов сервиса |
| PITR | восстановление базы на произвольный момент времени по бэкапу и WAL |
| PubAck | подтверждение NATS JetStream, что сообщение записано в поток |
| RACI | матрица ответственности: R делает, A отвечает, C консультирует, I информируется |
| Raft | алгоритм консенсуса для кластера из нечётного числа узлов; используется OpenBao и NATS |
| RBAC | управление доступом на основе ролей; в Umbrella роль + область по группам каталога |
| RE2 | движок регулярных выражений с линейным временем, без катастрофического перебора |
| RED | методика для сервисов: Rate, Errors, Duration |
| routing_key | ключ интеграции сервиса PagerDuty; хранится в OpenBao |
| RPO, RTO | допустимая потеря данных и время восстановления при аварии |
| S3 | объектное хранилище для бэкапов, размещается на другой площадке или в другом регионе |
| SAST | статический анализ исходного кода на уязвимости |
| SBOM | перечень компонентов и зависимостей образа или приложения |
| SCIM | протокол передачи пользователей и групп из IdP в приложение (push) |
| SIEM | система сбора и анализа событий безопасности; получает журнал аудита Umbrella |
| SLO, SLA | целевой уровень сервиса внутри команды; соглашение об уровне сервиса с потребителем |
| SSRF | атака, при которой сервер по запросу нарушителя обращается к внутренним адресам |
| STRIDE | классификация угроз: подмена, изменение, отказ от авторства, раскрытие, отказ в обслуживании, повышение прав |
| USE | методика для ресурсов: Utilization, Saturation, Errors |
| WAF | межсетевой экран уровня приложений для HTTP |
| WAL | журнал предзаписи PostgreSQL; используется для репликации и восстановления |
| Watchdog | контейнер самоконтроля: сквозная проба, проверка каналов, отставание резервной площадки, heartbeat |
| webhook | HTTP-запрос, которым система сама передаёт событие |
| алерт / тревога / инцидент | алерт — то, что уходит в PagerDuty (в целевой архитектуре один алерт на инцидент); тревога — все события с одним ключом дедупликации; инцидент — группа из одной или нескольких тревог одной проблемы с вероятной причиной |
| бизнес-услуга | то, что видит клиент; собирается из ИТ-сервисов, мастер — корпоративная ITSM |
| блок | шаг коннектора или правила в конструкторе |
| вероятная причина | КЕ, тревога на которой скорее всего вызвала остальные тревоги инцидента |
| группа каталога | группа корпоративного каталога; через привязку даёт роль, область и предустановки дашборда |
| дашборд инцидентов | страница веб-интерфейса Umbrella со списком инцидентов, фильтрами, поиском и действиями |
| запасная платформа оповещения | сторонний сервис оповещения, подключённый как один из резервных каналов |
| инвентарь | список объектов источника, из которого строится карта CMDB |
| инцидент | группа из одной или нескольких тревог одной проблемы с вероятной причиной; на него уходит один алерт PagerDuty |
| ИТ-сервис | технический сервис, из которого собрана бизнес-услуга |
| КЕ | конфигурационная единица: приложение, БД, хост, под, облачная логическая группа |
| кеш дежурств | копия расписаний на 7 дней вперёд и escalation policy PagerDuty в PostgreSQL; нужна, когда PagerDuty недоступен |
| коннектор | собранный из блоков способ забирать данные из источника и подтверждать получение |
| курсор | позиция в источнике, до которой события уже забраны |
| логическая группа | устойчивая единица в облаке, внутри которой меняются инстансы |
| нормализация | приведение события к единой модели |
| область | часть данных, на которую действует роль: бизнес-услуги, ИТ-сервисы, команды, коннекторы и источники |
| окно обслуживания | период работ, когда тревоги пишутся, но не отправляются |
| основной канал оповещения | PagerDuty |
| ПДн | персональные данные |
| плавающий ID | ID облачного ресурса, меняющийся после перезагрузки |
| предустановка дашборда | настройка дашборда для группы: фильтры по умолчанию, колонки, группировка, сортировка, виджеты, автообновление, правила контекста и папка Grafana |
| привязка группы | связь группы каталога с ролью, областью и предустановками; меняется в два ключа |
| резервные каналы | SMS, звонок, мессенджеры с кнопкой, почта, webhook и запасная платформа оповещения, по которым Umbrella оповещает, если PagerDuty не принял алерт |
| резервные контакты | контакты команды сервиса на случай, когда кеш дежурств пуст или старше 24 ч, и после последнего уровня escalation policy |
| роль | набор разрешений на функции Umbrella, например incident.ack или connector.publish |
| РСМ | ресурсно-сервисная модель: связи объект мониторинга → КЕ → ИТ-сервис → бизнес-услуга |
| связи контекста | low-code правила: условие, обход карты CMDB и панели, по которым Context Builder строит дашборд Grafana для инцидента |
| сигнал | тип проблемы из справочника, входит в ключ дедупликации |
| схлопывание | объединение событий разных источников про одну проблему в одну тревогу |
| тёплый резерв | вторая площадка с запущенными сервисами в минимальном составе и репликой данных; переключение за минуты |
| тревога | все события с одним ключом дедупликации |
| холодный резерв | резервная площадка без запущенных сервисов; система разворачивается из бэкапов |
| хранилище секретов | OpenBao ×3 на Raft; остальные части Umbrella хранят только ссылки |
| шаблон источника, шаблон события | правила перевода полей источника в единую модель; текст алерта для дежурного |
