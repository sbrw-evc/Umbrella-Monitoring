# Umbrella MVP · 8. Управление архитектурой

MVP стоит 28–34 человеко-месяца разработки и 1–1,5 штатной единицы на поддержку; лицензий нет, платный только PagerDuty. Ниже стоимость владения и эффекты, требования с трассировкой, журнал решений, ответственность, проверки, риски и ограничения.

## Журнал архитектурных решений

«Принято» означает решение заказчика, зафиксированное с датой; «Предложено» означает рекомендацию архитектора, которую нужно утвердить.

| № | Решение | Альтернативы | Обоснование | Статус |
| --- | --- | --- | --- | --- |
| ADR-01 | Своя разработка вместо готовой event-management платформы | коммерческие платформы, open source аналоги | нужен конструктор с ack в источник, устойчивые КЕ для облака и РСМ без лицензий | Предложено |
| ADR-02 | PagerDuty — основной канал оповещения, резервные каналы в Umbrella | только PagerDuty; своя полная доставка | готовые расписания и эскалации PagerDuty, но нельзя остаться без оповещения при его недоступности | Принято 30.09.2026 |
| ADR-03 | Go на бэкенде | Java, Python | производительность, один бинарник, SDK облаков | Принято 30.09.2026 |
| ADR-04 | NATS JetStream как шина | Kafka, RabbitMQ | хватает с запасом, проще в эксплуатации, есть request/reply | Предложено |
| ADR-05 | PostgreSQL; transactional outbox: изменение тревоги и запись outbox в одной транзакции | MongoDB, состояние в шине | реляционная карта CMDB, транзакции, alerts.changed не теряется | Предложено |
| ADR-06 | Конструктор коннекторов на своём движке в Go | Node-RED, Apache NiFi | ack после записи и inbox, один рантайм | Предложено |
| ADR-07 | Ack источнику только после записи в шину | ack сразу | нет потерь и дублей | Принято 30.09.2026 |
| ADR-08 | Устойчивая КЕ в облаке = логическая группа или тег | КЕ на каждый инстанс | ID меняется после перезагрузки | Предложено |
| ADR-09 | Без платных российских продуктов, open source допустим | — | требование заказчика | Принято 30.09.2026 |
| ADR-10 | Ключ дедупликации = КЕ + сигнал (+ метки) | хеш текста | работает между источниками | Предложено |
| ADR-12 | Все секреты только в OpenBao | зашифрованные поля в БД, Kubernetes Secrets | требование заказчика | Принято 30.09.2026 |
| ADR-13 | Fallback Notifier отдельным контейнером | внутри PagerDuty Gateway | отказ или ошибка в одном не выключает другой, отдельное масштабирование и права | Предложено |
| ADR-14 | Кеш дежурств из PagerDuty REST API каждые 5 мин | ручной список дежурных; запрос в момент аварии | в момент недоступности PagerDuty его API тоже может не отвечать | Предложено |
| ADR-15 | Резервные каналы только почта и webhook, подтверждение по одноразовой ссылке в Core API | сразу SMS и звонки | нет новых подрядчиков и затрат в MVP; SMS и звонки в целевой архитектуре | Предложено |
| ADR-20 | Дашборд инцидентов в собственном веб-интерфейсе, а не дашборд Grafana | дашборд Grafana поверх БД Umbrella; только список инцидентов PagerDuty | нужны права по областям, действия ack и silence с возвратом в источники, поиск по событиям и фильтры по РСМ | Принято 01.10.2026 |
| ADR-21 | Контекст в Grafana: дашборд генерируется по HTTP API из low-code связей | свои графики в Umbrella; один шаблонный дашборд с переменными в URL | Grafana уже читает хранилища телеметрии; шаблонный дашборд не учитывает связи КЕ из карты CMDB | Принято 01.10.2026 |
| ADR-22 | Ролевая модель: каталог — источник истины, группы → роли + области + предустановки; LDAPS или SCIM | локальные пользователи и роли в Umbrella; роли из claims IdP без синхронизации | единое управление доступом, отзыв не позже 15 мин, те же группы для Grafana | Принято 01.10.2026 |
| ADR-23 | Секреты только в OpenBao; начальные секреты: auto-unseal (transit второго экземпляра или KMS) либо Шамир 3 из 5 у хранителей | ручное распечатывание одним администратором; ключи в Kubernetes Secrets | нет единственного держателя ключа, нет секретов вне OpenBao; способ распечатывания выбирает ИБ | Предложено |

ADR-11, ADR-16…ADR-19 и ADR-24 относятся к целевой архитектуре и описаны в её наборе.

## Ответственность и проверка

Матрица RACI: R делает, A отвечает, C консультирует, I информируется.

| Активность | Владелец архитектуры | Инженеры мониторинга | Команда разработки | ИБ | Эксплуатация | Владельцы сервисов |
| --- | --- | --- | --- | --- | --- | --- |
| Архитектура и ADR | A, R | C | C | C | C | I |
| Коннекторы и шаблоны | A | R | C | I | I | I |
| Правила подавления и маршрутизация | A | R | I | C | I | C |
| Резервные контакты и каналы | A | R | C | C | R | C |
| Связи контекста и папки Grafana | A | R | C | C | C | C |
| Ролевая модель, привязки групп, предустановки дашборда | A | C | C | R | C | C |
| Членство в группах каталога | I | I | I | C | R | A |
| Разработка и тесты | A | C | R | C | C | I |
| Модель угроз и пентест | A | I | C | R | C | I |
| Эксплуатация, обновления, бэкапы, распечатывание OpenBao | A | I | C | C | R | I |

| Проверка | Критерий приёмки | Когда |
| --- | --- | --- |
| Нагрузочный тест | 10 000 событий в минуту, p95 от события до PagerDuty не больше 30 с | этап 2 и каждый релиз |
| Тест подтверждения | останов Connector Runtime между записью и ack: 0 потерь, 0 дублей | каждый релиз |
| Тест облачных ID | пересоздание инстанса не меняет КЕ | этап 3 |
| Тест резервного канала | блокировка PagerDuty: оповещение за 3 мин, без ack за 10 мин — резервным контактам, возврат без дублей | этап 5 и каждый релиз |
| Тест ссылки подтверждения | повторное открытие, чужой пользователь и истёкшая ссылка отклоняются | этап 5 и каждый релиз |
| Проверка контекста в Grafana | дашборд открывается не дольше 2 с, панели соответствуют правилу, права на папку только у команды | этап 5 и каждый релиз |
| Тест синхронизации прав | удаление из группы AD → доступ, сессии и команда Grafana отозваны не позже 15 мин; выдать права себе нельзя | этап 3 и каждый релиз |
| Тест дашборда инцидентов | фильтры, поиск, представления, CSV и групповые действия соблюдают область пользователя | этап 4 |
| Хаос-тест | потеря узла приложений, NATS или PostgreSQL без потери алертов | до эксплуатации |
| Учения по восстановлению | восстановление из S3 и распечатывание OpenBao укладываются в RTO 1 ч, потеря данных не больше 1 мин | до эксплуатации, далее раз в квартал |
| Watchdog | сквозная проба раз в минуту, проверка каналов раз в сутки | постоянно |
| Пентест и ревью модели угроз | нет открытых уязвимостей высокого уровня | до эксплуатации, далее раз в полгода |

## Риски и ограничения

| Риск | Вероятность | Влияние | Мера |
| --- | --- | --- | --- |
| Источники и облака без устойчивых тегов дают много событий «без КЕ» | высокая | среднее | политика тегов, очередь «без КЕ», сервис PagerDuty по умолчанию |
| Umbrella становится единой точкой отказа оповещения | средняя | высокое | две реплики каждого сервиса, ingress, Watchdog и CMDB Discovery без единой точки отказа, внешний heartbeat, резервные каналы, план возврата к прямым интеграциям |
| PagerDuty и почта недоступны одновременно (общий сбой интернета) | низкая | высокое | корпоративный релей и webhook во внутренний мессенджер идут внутри сети; SMS и звонки в целевой архитектуре |
| Письма резервного канала попадают в спам или не читаются ночью | средняя | высокое | отдельный отправитель в белом списке, ежедневная проверка, эскалация через 10 мин; звонки в целевой архитектуре |
| Кеш дежурств устарел | низкая | среднее | обновление каждые 5 мин; кеш пуст или старше 24 ч → резервные контакты сервиса |
| Потеря ключей распечатывания OpenBao | низкая | высокое | auto-unseal или Шамир 3 из 5 у разных хранителей, учения раз в полгода, снапшоты Raft в S3 |
| Grafana недоступна | средняя | низкое | дашборд инцидентов и оповещение работают; ссылка показывает ошибку; разбор по боковой панели Umbrella |
| Каталог или IdP недоступен | низкая | среднее | последние синхронизированные группы сохраняются, break-glass администратор с MFA и аудитом |
| Карта CMDB неполна, и дашборд в Grafana не показывает нужные КЕ | средняя | среднее | дашборд по умолчанию со сводкой, отчёт «Инциденты без связей контекста», dry-run правил на реальных инцидентах |
| Конструктор и редакторы слишком сложны для инженеров | средняя | высокое | библиотека шаблонов и правил, dry-run, юзабилити-тесты |
| Сроки MVP недооценены | средняя | среднее | пять этапов с демонстрацией, новые функции в этапах 3–5 можно сдвинуть на пилот без влияния на оповещение |

Ограничения MVP:

- Резервные каналы только почта и webhook; SMS, звонки и мессенджеры с кнопкой в целевой архитектуре.
- Метрики, логи и трейсы не хранятся, графики показывает Grafana; истории событий дольше 30 дней нет.
- Связь тревог детерминированная (КЕ, сигнал, RED и USE), без топологической корреляции; инцидент на дашборде — одна тревога.
- Бизнес-услуги задаются вручную, интеграции с корпоративной CMDB нет.
- Одна площадка, восстановление из бэкапов, RTO 1 ч.
- Платные российские продукты не используются; все секреты только в OpenBao.
